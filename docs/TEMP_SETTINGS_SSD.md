# 临时 SSD：EcRoom 设置体系重设计

本文件用于本轮设置体验重构。完成后，核心原则合并进 `ECROOM_SSD.md`，临时文件可保留为设计记录。

## 1. 设计目标

EcRoom 的设置不是开发者后台，也不是简单照搬 ChatGPT。它应借鉴 ChatGPT 的“轻量弹窗 + 左侧分区 + 右侧清晰操作”模式，但内容必须服务于本项目：

- 创作模型连接；
- 个人资料；
- 偏好记忆；
- 创作数据；
- 工作规则复审；
- 本地安全边界。

设置应作为 modal 出现，不应该把用户带离当前创作上下文。

## 2. 分区模型

```text
常规
  个人显示名、简介、主题入口、运行状态

模型
  当前服务商、模型、连接状态、API Key、本地 stub 说明

个性化
  已保存偏好、候选策略、完成后学习开关

数据管理
  对话记录、作品库、偏好记忆、项目资料、工作规则建议、导出/危险操作

工作规则
  自动提出改进建议开关、技能运行记录开关、最低评测样本
```

## 3. 数据管理语义

旧语义：

```text
仅删除对话
清理本次记忆
彻底删除
```

问题：

- 这是单条对话删除 modal 的内部动作，不是全局数据管理；
- 用户无法理解“本地记忆”包含什么；
- “彻底删除”太笼统，容易误解为删除整个项目。

新语义：

| 数据类型 | 用户理解 | 默认操作 |
| --- | --- | --- |
| 对话记录 | 左侧历史中的创作过程 | 在对话菜单中管理 |
| 已完成作品 | 作品库中的可复用成果 | 去资产库管理 |
| 偏好记忆 | 用户确认保存的长期偏好/项目规则 | 在个性化中查看和删除 |
| 项目资料 | 导入的链接、规范、设定、canon | 后续独立项目资料页管理 |
| 工作规则建议 | 创作助理想调整自己的方式 | 在对话角落复审 |
| 本地工作区 | 上面所有数据的本机存储 | 提供导出和危险区说明 |

## 4. ChatGPT 可借鉴部分

可借鉴：

- 设置为居中弹窗，不切走主界面；
- 左侧为稳定导航；
- 右侧每行是一个明确设置项；
- 数据管理用“管理/导出/删除”等动作按钮；
- 危险动作单独放底部。

不能照搬：

- 远程浏览器数据、共享链接、营销隐私等不属于本地创作系统；
- “为所有用户改进模型”不适合 EcRoom，应改为“允许本地评测与工作规则建议”；
- 账号/账单/家长控制等不应出现在当前产品。

## 5. 模型设置原则

用户需要看到：

- 当前是否启用真实模型；
- 当前 provider / model；
- API Key 是否已保存；
- 连接测试结果；
- 高级 Base URL 可折叠。

用户不需要看到：

- 大段 provider 解释；
- 没有启用的调试字段；
- 让普通用户困惑的内部 LLM 错误栈。

## 6. UI 验收

- 点击侧边栏设置图标打开 modal，而不是切到整页；
- 设置 modal 左侧分区，右侧内容；
- 数据管理不再显示“仅删除对话/清理本次记忆/彻底删除”三张卡；
- 数据管理按 EcRoom 数据对象解释；
- 单条对话删除 modal 保留，但文案改为“从历史移除 / 撤销本次未确认学习 / 删除本次原始文件”；
- 模型设置显示运行状态和连接测试；
- 全量测试和 JS 语法检查通过。
