# 临时 SSD：创作助理改进建议复审

本文件用于本轮 UI/产品逻辑改造。完成后，核心原则应合并回 `ECROOM_SSD.md`，临时文件可删除或归档。

## 1. 问题

当前 `工作规则改进` 面板直接出现在输入框下方，会造成三个问题：

- 视觉上挤压创作区，用户正在写反馈时被系统工程信息打断；
- 内容是 harness 路径和英文技术描述，普通用户无法判断它和创作有什么关系；
- 只有应用入口，没有忽略入口，用户无法快速处理下一条建议。

## 2. 产品语义

这不是给用户看的工程 diff，而是“创作助理请求调整自己的工作方式”。

用户需要理解的是：

```text
我发现这次有一个可改进点。
以后遇到类似创作时，我是否应该这样调整工作方式？
```

内部 harness 路径、validation plan、rollback plan 只属于高级技术细节，默认折叠。

## 3. 交互设计

入口：

- 在对话页右上角或不干扰正文的角落显示一个小图标按钮；
- 有待处理建议时显示数量徽标；
- 默认不展开，不占用输入框下方空间。

弹窗：

- 点击图标后打开居中 modal；
- 每次只展示一条建议；
- 主体使用用户可理解的中文说明；
- 底部两个主动作：`忽略` 和 `应用`；
- 点击任意一个后进入下一条；
- 所有建议处理完后关闭 modal 并隐藏徽标。

信息结构：

```text
标题：是否调整我的工作方式？
说明：我发现这次可能需要更早检查角色设定一致性。
以后我会：先确认角色口吻、时间线和不可改动设定，再改成适合平台发布的版本。
适用范围：仅这个创作项目 / 类似平台内容 / 长期工作方式
可能影响：短内容会多一次检查，但能减少角色跑偏。
按钮：忽略 / 应用
折叠：技术细节
```

## 4. 作用域原则

改进建议必须默认保守：

- 涉及 canon、角色、世界观、项目设定：默认作用于当前项目；
- 涉及平台规范：默认作用于对应平台任务，不代表所有创作；
- 涉及自然度、模板感：默认作用于类似内容类型，只有用户长期确认后才沉淀为全局工作方式；
- 没有明确证据或评测结果：只能作为待复审建议，不能自动应用。

用户点击 `应用` 的含义：

- 不是“永远改变所有任务”；
- 是“同意把这条工作方式写入对应 harness 规则”，仍受 target component 和项目/平台语境约束；
- 如果 A/B gate 不足，后端必须要求人工说明或阻止应用。

用户点击 `忽略` 的含义：

- 当前建议不采用；
- 记录 ignored 状态，避免同一条在当前 session 反复出现；
- 不删除失败信号和 evidence，后续若多次复现仍可再次提出更强证据的建议。

## 5. 技术落点

后端：

- manifest proposal 支持状态更新：`ignored` / `applied_pending_validation`；
- 新增 ignore endpoint；
- session_view 返回 proposals 时过滤/标记状态；
- apply 和 ignore 都记录 metric。

前端：

- 删除 chat composer 下方常驻 evolution panel；
- 新增角落图标入口；
- 新增 centered review modal；
- 前端将 proposal 翻译成用户可理解文案；
- 点击应用/忽略后自动进入下一条。

## 6. 验收

- 输入框下方不再显示大块工作规则面板；
- 有建议时角落图标显示数量；
- modal 每次只展示一条；
- 应用和忽略都会进入下一条；
- 忽略后当前 session 不再展示该建议；
- 技术细节默认折叠；
- 全量测试通过，浏览器可正常加载。
